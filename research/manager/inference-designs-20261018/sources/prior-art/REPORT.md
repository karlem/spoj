## Decision

Both starting ideas substantially overlap existing implementations. A persistent application graph, prefix sharing, and stable reduction of partial attention are established mechanisms. A useful SPOJ experiment must isolate an unmet combination of lifecycle correctness, heterogeneous capacity, and task completion cost. Extend an existing engine if its supported interfaces suffice; a new engine or kernel has not yet earned its cost.

The decisive near-term pair is:

- **H1: explicit ownership and cancellation across persistent branches.** Test a branch-state contract under tool waits and asynchronous device work against SGLang's existing program/fork/cache behavior and a task-aware scheduler. The possible contribution is an auditable lifecycle and admission mechanism for the chosen workload, not discovering DAGs or copy-on-write.
- **H2: attention over resident KV on unequal workers.** Test whether capacity gained by keeping KV beside its owner offsets slowest-worker compute, query/reduction traffic, and synchronization. Compare supported vLLM/SGLang decode context parallelism first. The reduction algebra itself has no novelty claim.

## Seven decisive primary-source families

1. **SGLang / RadixAttention** — Lianmin Zheng et al., *SGLang: Efficient Execution of Structured Language Model Programs*, [arXiv:2312.07104](https://arxiv.org/abs/2312.07104), first submitted 2023. This run inspected the abstract and implementation, not the entire paper. At pinned revision [`05ce0e9`](https://github.com/sgl-project/sglang/tree/05ce0e980f00aa80864190d6f1cd5d9b685802f1), [`interpreter.py`](https://github.com/sgl-project/sglang/blob/05ce0e980f00aa80864190d6f1cd5d9b685802f1/python/sglang/lang/interpreter.py) has `fork`, copies program state, and synchronizes before branching. [`radix_cache.py`](https://github.com/sgl-project/sglang/blob/05ce0e980f00aa80864190d6f1cd5d9b685802f1/python/sglang/srt/mem_cache/radix_cache.py) has prefix-tree state, lock references, and eviction. **Already implemented:** structured execution, branching, shared prefix reuse, cache protection/reclamation machinery. **Not established by this inspection:** exact cancellation guarantees across every asynchronous transport/backend or whether a new API improves a real agent trace. Crucially, the same pinned tree also has [DCP documentation](https://github.com/sgl-project/sglang/blob/05ce0e980f00aa80864190d6f1cd5d9b685802f1/docs/docs/advanced_features/dcp.mdx), [communication](https://github.com/sgl-project/sglang/blob/05ce0e980f00aa80864190d6f1cd5d9b685802f1/python/sglang/srt/layers/dcp/comm.py), and [LSE reduction kernels](https://github.com/sgl-project/sglang/blob/05ce0e980f00aa80864190d6f1cd5d9b685802f1/python/sglang/kernels/ops/attention/dcp_kernels.py). These stripe KV by position, compute owner-local partial attention, and merge outputs with LSE. Main documented paths and compositions have explicit model/hardware restrictions; this is not evidence that an arbitrary CPU donor works.

2. **Parrot** — Chaofan Lin et al., *Parrot: Efficient Serving of LLM-based Applications with Semantic Variable*, OSDI 2024; [paper](https://arxiv.org/abs/2405.19888), [pinned repository](https://github.com/microsoft/ParrotServe/tree/a72ad158604661e06b5ea38db5dcc026884a398c). The [semantic-variable contract](https://github.com/microsoft/ParrotServe/blob/a72ad158604661e06b5ea38db5dcc026884a398c/docs/sys_design/app_layer/semantic_variable.md) separates asynchronous `submit` and `get`; a variable persists across requests and exposes dependencies. The [graph executor](https://github.com/microsoft/ParrotServe/blob/a72ad158604661e06b5ea38db5dcc026884a398c/parrot/serve/session/graph_executor.py) has context readiness, fill/generate primitives and execution tasks; scheduler source was also inspected. **Already implemented:** application DAG visibility, cross-request context reuse, DAG-aware scheduling and performance objectives. **Gap to test:** a precisely specified tool-wait/cancel/admission contract on a supported modern engine. The README marks Parrot an unmaintained research prototype and records security changes that intentionally disable historical APIs; use its architecture as a baseline specification, not an unqualified deployable dependency. Paper-era results and current patched source are not interchangeable.

3. **PagedAttention / vLLM** — Woosuk Kwon et al., *Efficient Memory Management for Large Language Model Serving with PagedAttention*, SOSP 2023; [paper](https://arxiv.org/abs/2309.06180). **Already demonstrated in the paper:** paging-inspired KV allocation and flexible sharing within/across requests. Thus a memory allocator with shared prefixes is not a fresh engine principle. Current [pinned context-parallel documentation](https://github.com/vllm-project/vllm/blob/7879f3687b5b6a4be4754242e70b9c21cf7b4183/docs/serving/context_parallel_deployment.md) explicitly supports DCP for **GQA and MLA**, describes interleaved KV ownership, and explains that more DCP reduces KV duplication but increases communication. Its stated DCP arrangement reuses TP ranks; this does not establish support for an arbitrary independent heterogeneous donor. **Strongest H2 baseline:** the supported model/backend's DCP implementation, alongside a same-capacity local run where possible. Separate capacity benefit from latency benefit.

4. **Flash-Decoding** — Tri Dao, Daniel Haziza, Francisco Massa, and Grigory Sizov, [Stanford CRFM technical article, 2023-10-12](https://crfm.stanford.edu/2023/10/12/flashdecoding.html). **Already implemented:** split K/V along sequence length, compute partial attention in parallel, return a partial output plus per-row LSE, and reduce those results. The article links released FlashAttention and xFormers implementations; the [FlashAttention README](https://github.com/Dao-AILab/flash-attention/blob/965c9212e6be33c821ee9f2b461564c5c91a2503/README.md) was additionally pinned. This is a within-GPU parallelization technique, so its published throughput does not predict a network deployment. **Consequence:** exact-real-arithmetic summary merging is a known primitive. Our next question is placement, lifetime, and communication cost, not inventing the merge.

5. **Ring Attention** — Hao Liu, Matei Zaharia, and Pieter Abbeel, [*Ring Attention with Blockwise Transformers for Near-Infinite Context*, arXiv:2310.01889v4](https://arxiv.org/html/2310.01889v4), 2023 technical version. Full HTML was retrieved; architecture, overlap analysis, and inference appendix were inspected. [Author implementation](https://github.com/lhao499/llm_large_context/tree/d2ea1af9a288f85ea2fd74690ece1c16d2eebc83) was pinned at README depth. **Already proposed:** sequence-distributed attention and blockwise compute/communication overlap. **Distinction:** it circulates K/V blocks; a decode worker retaining KV and receiving one query is a different communication schedule. Training/large-query-block overlap cannot be imported into batch-one decode. Do not cite the paper's general overlap claim as measured commodity-network evidence. The appendix's simplified inference example was not reproduced or used as our cost model.

6. **DistServe** — Yinmin Zhong et al., *DistServe: Disaggregating Prefill and Decoding for Goodput-optimized Large Language Model Serving*, OSDI 2024; [paper](https://arxiv.org/abs/2401.09670), [pinned README](https://github.com/LLMServe/DistServe/blob/82831f1604cc6b10bebd360f6c437a07790dde9f/README.md). **Already proposed/implemented:** different resources and parallelism for prefill and decode, with KV movement and SLO-based planning. **Distinct baseline:** phase disaggregation is not sequence/KV sharding within each decode step. Its resource duplication and handoff costs must be charged; do not compare a multi-GPU candidate with a one-GPU baseline as if resources were equal.

7. **Mamba / Mamba-2** — Albert Gu and Tri Dao, [*Mamba: Linear-Time Sequence Modeling with Selective State Spaces*](https://arxiv.org/abs/2312.00752); Tri Dao and Albert Gu, [*Transformers are SSMs: Generalized Models and Efficient Algorithms Through Structured State Space Duality*](https://arxiv.org/abs/2405.21060), Mamba-2 / ICML 2024 as the repository citation records. At [pinned code](https://github.com/state-spaces/mamba/tree/e9594ce1c732d97440f0332fdc43170a2294dbfa), [`mamba_simple.py`](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/mamba_ssm/modules/mamba_simple.py) and [`mamba2.py`](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/mamba_ssm/modules/mamba2.py) expose recurrent convolution/SSM state and step/cache methods. **Queued co-design:** make that bounded recurrent state a versioned, forkable session object. This changes model architecture and generally requires different weights/training and quality evaluation; it does not preserve an arbitrary transformer's outputs.

## H1: experiment contract

Represent a state handle as `(model identity, tokenizer/context identity, position, branch, generation)`, with a ledger of immutable shared prefix blocks, mutable branch tail, committed output, sampler/RNG state, and outstanding device/transport readers. Operations are `fork`, `advance`, `suspend`, `resume`, `cancel`, and `release`; exact names are illustrative. A cancelled branch must not publish new output after cancellation takes effect, but its buffers cannot be reclaimed until device and transfer readers quiesce. A generation identifier prevents a late completion from writing into a recycled slot. Shared siblings remain valid. Admission reserves memory for the next bounded operation, not an unbounded predicted lifetime.

**Small prototype now:** a deterministic event-driven state machine with injected reordered completions, duplicate completions, cancellation during DMA, tool return after cancellation, memory pressure, and sibling continuation. Check absence of use-after-free, exactly one committed completion, conservation of allocated bytes, eventual reclamation after quiescence, and no duplicate external tool side effects. Tool execution needs an idempotency/commit contract outside token state; an inference cache cannot provide exactly-once external effects by itself.

**Next actual experiment:** one supported model and engine, with repeated fixed-prefix branches, varied tool waits and cancellation rates. Compare (a) ordinary engine prefix caching/batching with the same task runner, (b) SGLang program/fork semantics plus available scheduling controls, and (c) the proposed explicit-lifecycle extension. Hold quantization, model, task inputs, outputs/quality criteria, concurrency and hardware fixed. Measure peak and byte-seconds of resident state, completed-task latency distribution, useful versus cancelled compute, queue delay, and reclaimed-buffer delay. Warm and cold runs must be separated. Do not compare only with full prefix copying or a deliberately serial runner.

**Falsifier:** correctness failure rejects the contract; no material task-latency or memory benefit over the strongest supported extension rejects a separate engine. Predeclare a practical threshold, such as 20% lower peak memory without degrading completed-task p95 latency, for a specified workload family. Shared prefixes already optimized by the baseline, short waits, non-cancellable kernels, or bookkeeping overhead may erase the gain. This threshold is a proposal for a future preregistration, not a result.

## H2: experiment contract and cost accounting

Each KV owner retains immutable committed token rows plus an uncommitted append. For a query head and local visible rows, compute score maximum `m`, scaled normalizer `l = sum(exp(score-m))`, and scaled weighted vector `u = sum(exp(score-m)*v)`. Merge partitions by `m=max(m_i)`, `l=sum(exp(m_i-m)*l_i)`, `u=sum(exp(m_i-m)*u_i)`, and return `u/l`. Empty partitions use a defined identity; all-masked input has an explicit contract rather than dividing by zero. Equivalent normalized-output/LSE representation is used in established implementations.

The identity is exact in real arithmetic; floating-point reduction order and precision can change values and sampled tokens. Verify against high-precision dense attention with error tolerances, extreme scores, uneven/empty shards, masks, rotary positions, GQA mapping, and different shard/merge orders. Test append visibility, branch epochs, lost/duplicate replies and cancellation separately. No token may be committed using a missing or stale required shard; partial completion cannot silently substitute approximate attention.

For GQA, query count `Hq` and stored KV-head count `Hkv` differ. Each query head must use its assigned KV head. Query and partial-output traffic scales with `Hq`; KV capacity and append traffic scale with `Hkv`. With FP16 Q/K/V, FP32 `m,l,u`, `Hq=32`, `Hkv=8`, and head dimension 128, a remote worker receives 8,192 query bytes and returns 16,640 summary bytes per layer before protocol overhead. A newly appended full KV row is 4,096 bytes per layer, sent to its owner as required by placement. A 32,768-token KV cache is 128 MiB per layer. These are logical byte counts, not wire measurements, and do not imply a latency ratio. Multiple remote owners multiply query and summary traffic; collective topology changes total and critical-path bytes.

**Strongest comparison:** local attention at equal usable capacity; supported vLLM GQA DCP/SGLang DCP; resident-donor scheme; and any necessary KV-transfer alternative. Keep model weights/accounting equal or report why the capacity experiment prevents equality. For latency, the distributed layer cannot finish before the slowest required shard's queue, compute, and communication path plus merge. Across dependent layers that delay accumulates. Include startup, initial KV placement, new-token append, owner metadata, output reduction, host/device copies, retries and finite network queues. H2 does not solve weight capacity or autoregressive dependence.

**Smallest discriminating next step:** after the manager's pure arithmetic identity test, run one attention layer with actual cached tensors on available hardware and matched local/DCP paths. Sweep context length, one versus several owners, shard balance, and injected delay. First classify capacity-only versus latency wins. Predeclare a gain threshold before running. Reject broad distribution when the same-capacity local engine fits and wins; reject a heterogeneous shard placement if its slowest donor dominates despite reduced bytes. A correct CPU fixture establishes the algebra and protocol cases only, never cluster speed.

## Queued third design: recurrent-state engine

Keep Mamba/SSM state resident and fork by snapshotting or copy-on-write of recurrent state. Unlike append-only transformer KV, recurrent state is updated every step: after a fork, both branches soon need independent copies of the full mutable state. Budget convolution state, SSM state, RNG, model/backend identity, and any replay/checkpoint log. Fixed state per branch is independent of context length for the inspected pure recurrent layers, but scales with model width, number of layers, and live branches; hybrids may retain attention KV too.

A useful future test compares long tool-rich tasks at matched quality, then records state bytes, fork/restore cost, completion latency and energy. Retrieval and long-range reasoning failures can negate memory savings. A new training effort belongs to a separately budgeted project; no checkpoint download, training, or quality claim occurred here.
